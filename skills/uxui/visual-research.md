# Skill: Visual Research

## Por qué investigar referentes antes de diseñar

Diseñar sin investigar el sector equivale a ignorar 10 años de aprendizaje colectivo sobre qué funciona para tus usuarios. Los usuarios del sector ya tienen expectativas visuales formadas. Cumplirlas bien es tabla. Superarlas es diferenciación. Ignorarlas es fricción.

## Proceso de investigación

### 1. Mapear el landscape del sector

```
Para el tipo de producto que se va a construir, identificar:

Competidores directos (3-5):
→ Productos que resuelven el mismo problema
→ Fuente: Google, Product Hunt, App Store

Referentes aspiracionales (3-5):
→ Productos en sectores adyacentes con excelente diseño
→ Pueden ser de sectores distintos pero con usuarios similares
→ Fuente: Dribbble, Mobbin, Awwwards, Httpster

Líderes de categoría (2-3):
→ Los productos más usados del sector, aunque no sean los mejores diseñados
→ Definen las convenciones que los usuarios ya conocen
```

### 2. Extraer patrones visuales

Para cada referente, documentar:

```markdown
## [Nombre del producto]
**URL/App Store**: [link]
**Por qué es relevante**: [1 frase]

### Paleta de colores
- Color primario: [hex] — [cómo se usa]
- Color de fondo: [hex]
- Color de texto: [hex]
- Color de acento: [hex si hay]

### Tipografía
- Fuente principal: [nombre]
- Estilo: [serif / sans-serif / monospace]
- Pesos usados: [bold para títulos, regular para cuerpo, etc.]

### Estilo visual general
[Minimal / Bold / Warm / Technical / Playful / Premium / etc.]

### Patrones de UI notables
- [Patrón 1: e.g., "bottom navigation con 4 items"]
- [Patrón 2: e.g., "cards con sombra sutil, no bordes"]
- [Patrón 3: e.g., "imágenes circulares para avatares"]

### Qué hace bien
- [Fortaleza visual 1]
- [Fortaleza visual 2]

### Qué hace mal o qué se podría superar
- [Oportunidad 1]
```

### 3. Identificar patrones dominantes del sector

Después de analizar todos los referentes, sintetizar:

```markdown
## Patrones que dominan el sector

### Paleta de colores
- Color dominante del sector: [descripción — e.g., "azules y blancos en fintech"]
- Razón psicológica: [por qué ese color domina en este sector]
- Oportunidad: [qué color podría diferenciarnos sin romper las expectativas]

### Tipografía
- Estilo dominante: [e.g., "sans-serif geométricas (Inter, DM Sans) en casi todos"]
- Razonas: [legibilidad en pantallas pequeñas, sensación tech moderna]
- Excepción notable: [si algún referente usa algo distinto con éxito]

### Patrones de navegación
- [Patrón que usan el 80% — e.g., "bottom navigation en mobile"]
- [Patrón que usan todos — e.g., "search bar prominente en la home"]

### Convenciones visuales que los usuarios esperan
- [Convención 1: los usuarios del sector esperan esto]
- [Convención 2: romperla generaría fricción]

### Oportunidades de diferenciación
- [Área donde los competidores son débiles]
- [Elemento visual que nadie ha explorado bien]
```

### 4. Fuentes para investigación

```
Apps reales (para UI patterns móviles):
→ Mobbin (mobbin.com) — la base de datos más completa de UI patterns
→ App Store / Google Play — screenshots y valoraciones reales

Diseño web:
→ Awwwards (awwwards.com) — premiados por calidad de diseño
→ Httpster (httpster.net) — sitios con diseño destacable
→ Landings (landings.dev) — landing pages de alto nivel

Diseño de producto / SaaS:
→ Dribbble — explorar por categoría
→ Behance — casos de estudio con proceso completo
→ SaaSFrame (saasframe.io) — patrones de UI de SaaS

Tipografías:
→ Google Fonts — free, excelente calidad
→ Fontshare — fuentes premium gratuitas
→ Type Scale (typescale.com) — previsualizar escalas tipográficas

Paletas de color:
→ Coolors (coolors.co) — generador de paletas
→ Realtime Colors (realtimecolors.com) — preview en UI real
→ Huemint (huemint.com) — paletas con IA
→ ColorHunt (colorhunt.co) — paletas curadas
```

```markdown
## Referentes analizados
[Tabla con los referentes y por qué se eligieron]

## Patrones dominantes del sector
[Síntesis de los patrones visuales que dominan]

## Convenciones que los usuarios ya esperan
[Lista de convenciones que NO se deben romper sin razón muy fuerte]

## Oportunidades de diferenciación
[Dónde el sector es débil y hay espacio para destacar]

## Recomendación de dirección visual
[1-2 párrafos describiendo la dirección visual recomendada basada en la investigación]
→ Input directo para la skill brand-identity
```

## Checklist de investigación completa

- [ ] Mínimo 5 referentes analizados (mix de competidores directos + aspiracionales)
- [ ] Patrones de color documentados para todos
- [ ] Tipografía documentada para todos
- [ ] Patrones de UI documentados (navegación, cards, estados)
- [ ] Síntesis de patrones dominantes completada
- [ ] Oportunidades de diferenciación identificadas
- [ ] Recomendación de dirección visual escrita
